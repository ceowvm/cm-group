# Аудит готовности CM Group Mini App

Дата аудита: 29.07.2026

## Критические проблемы исходной версии

### 1. Профиль хранился только в localStorage — исправлено

Ранее имя, телефон, ответы и доступ существовали только в конкретном браузере. На другом телефоне или компьютере пользователь начинал заново.

Теперь профиль сохраняется на сервере с ключом по подтверждённому Telegram ID и загружается при следующем входе с того же аккаунта.

### 2. Telegram ID использовался без проверки — исправлено

`initDataUnsafe.user` нельзя использовать как серверную авторизацию: данные на клиенте можно подменить.

Теперь приложение отправляет исходный `Telegram.WebApp.initData`, а PHP проверяет HMAC-подпись и срок действия данных до доступа к профилю.

### 3. `sendData()` конфликтовал с личным кабинетом — исправлено

В исходной версии `sendData()` вызывался при сохранении имени, телефона, расчёта и других действиях. Telegram закрывает Mini App после `sendData()`, и этот метод доступен только для Mini Apps, открытых reply-кнопкой.

Теперь события передаются в собственный API без закрытия приложения. Возврат в бот выполняется отдельной явной кнопкой.

### 4. Не было серверной части и базы — исправлено

Добавлен PHP API с автоматическим хранением в SQLite или защищённых JSON-файлах. Профили и события хранятся на хостинге REG.RU.

### 5. Не было фактической интеграционной точки для SaleBot — подготовлено

Добавлен серверный HTTPS webhook с HMAC-подписью. Для завершения связи требуется только URL webhook, который выдаст SaleBot/CRM.

## Ошибки и недочёты интерфейсного кода

- некорректное состояние из localStorage могло сломать экран — добавлена полная нормализация состояния;
- старый удалённый ответ `lt100` мог сохраняться — фильтруются только актуальные ответы;
- неверный экран или продукт приводил к ошибкам — добавлены безопасные значения по умолчанию;
- калькулятор принимал значения вне диапазона и `NaN` — добавлена проверка и ограничение;
- телефон проверялся только по минимальному количеству цифр — добавлен диапазон 10–15 цифр;
- политика персональных данных была только уведомлением — открывается действующая страница `cmgroup.pro/policy`;
- кнопка сброса демо была видна пользователям — теперь доступна только с `?debug=1`;
- не было статуса синхронизации — добавлены статусы «Сохранено», «Сохраняем», «Ошибка» и локальный режим;
- Kinescope-страница вставлялась как файл `<video>` в карточке QUICK START — теперь открывается корректной ссылкой;
- отсутствовали связанные `label` у полей — исправлено;
- отсутствовали серверные security headers и запрет просмотра каталогов — добавлены `.htaccess`;
- отсутствовала автоматическая проверка синтаксиса — добавлен GitHub Actions workflow.

## Что требует ручной настройки перед боевым запуском

1. Создать на сервере `api/config.local.php` и вставить токен Telegram-бота.
2. В SaleBot открыть приложение через inline Web App / Menu Button, чтобы Telegram передавал `initData` пользователя.
3. Получить в SaleBot URL входящего webhook и добавить его в `event_webhook_url`.
4. Проверить права записи папки `api/storage`.
5. Выполнить тест на двух устройствах с одним Telegram-аккаунтом.

## Что сознательно не изменено

- тексты полного «Описания профиля» и «Главной точки роста» пока одинаковы для всех пользователей — их персонализация требует утверждённой контентной матрицы;
- проценты калькулятора 17% и 12% оставлены без изменения как действующая бизнес-логика;
- видео остаются на внешних серверах SaleBot/Kinescope.
